## Где находятся снапшоты

В корне проекта есть обычная папка **`snapshots/`**. Список в окне «Снапшоты» соответствует JSON-файлам в этой папке. Их можно также открыть в Finder или скопировать вручную. Файлы и содержимое планов не включаются в публичный GitHub.

В историю скопированы 8 исходных файлов из `1.0 MP`, от `rhm-dashboard-2026-05-04.json` до `rhm-dashboard-2026-09-11.json`. Исходники не изменялись. У старых файлов дата берётся из имени, а не из времени их копирования в папку.

При каждом открытии страницы автоматически загружается последний по дате снапшот. Его имя отображается в заголовке дашборда и вкладки. Предыдущий браузерный черновик при отличии доступен через откат после загрузки. При недоступности файлов остаётся локальный черновик и показывается ошибка.

## Файловое окно

- **Сохранить**: имя с текущей датой и временем заполняется автоматически, например `rhm-dashboard-2026-09-14_17-00.json`. Имя можно изменить перед записью. Повторные автоматические сохранения в одну минуту получают суффиксы `(2)`, `(3)` без перезаписи файла. Клик по заголовку «Дата» меняет порядок сортировки.
- Клик по имени/строке файла: подтверждение, затем загрузка.
- Карандаш: переименование настоящего файла в папке.
- Поле комментария: редактирование, Enter или галочка сохраняет; Escape отменяет.
- Корзина: подтверждение удаления. Файл перемещается в `snapshots/.trash/`; сразу после удаления доступна кнопка восстановления. Совпадение имён при сохранении, переименовании и восстановлении не перезаписывает другой файл.
- Меню **⋮** справа от «Снапшотов»: экспорт и импорт JSON-файла.

Комментарии, стабильный идентификатор и даты сохраняются внутри JSON в поле `_snapshot`; данные плана остаются в поле `resources`. Старые файлы без `_snapshot` также читаются. Переименование и комментарий не меняют исходную дату снапшота и его положение в истории.

Изменения на доске автоматически сохраняются в браузере как черновик, но **файл обновляется только при явном сохранении снапшота**. При новом открытии, по запросу владельца, снова открывается последняя сохранённая версия.

## Локальный запуск

Node.js 22+:

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

Открыть http://127.0.0.1:5173. По умолчанию API использует папку `snapshots/`. Переопределение: `RHM_LOCAL_SNAPSHOTS_DIR`.

```sh
npm test
npm run build
```

`npm run preview` показывает статическую сборку без API; для полного сценария используйте `npm run dev`.

## Сайт и будущее размещение

GitHub: https://github.com/saintano/rhm-dashboard

Vercel: https://rhm-dashboard-orpin.vercel.app

На опубликованном сайте предыдущая версия сохраняет отдельные JSON в private Vercel Blob `rhm-dashboard-snapshots`, префикс `rhm-snapshots/v1/`. Это облачная папка, отдельная от локальной `snapshots/`. Текущие локальные правки и 8 исторических файлов туда не отправлялись.

После одобрения локальной версии код публикуется push в `main`, который запускает автодеплой. Историю файлов нужно перенести в Blob отдельно; включать рабочие JSON в репозиторий не нужно. Серверный адаптер обновлён для комментариев, переименования и обратимого удаления, но эти облачные изменения ещё не опубликованы и не проверены на production.

Секреты из `.env.local` используются только сервером. `.env*`, `.vercel/`, `snapshots/` и `.local/` исключены из Git. Старые локальные тестовые снапшоты первой итерации оставлены в `.local/snapshots/`, в новую историю не включены.

**Не повышать APP_VERSION:** `dashboard-state-v4` содержит рабочий браузерный черновик.
